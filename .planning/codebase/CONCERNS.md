# Codebase Concerns

**Analysis Date:** 2026-11-04

## Tech Debt

**Unfinished features in `common` templates:**
- Issue: Several code paths are stubbed or deferred with TODO markers.
- Files: `charts/library/common/templates/lib/pod/_affinity.tpl` (fails with `TODO: not implemented`), `charts/library/common/templates/class/_storageClass.tpl` (empty `parameters: {{/* TODO: */}}`), `charts/library/common/templates/spawner/_cnpg.tpl` (no handling of PostgreSQL version updates, line ~47; custom queries configmaps not created, line ~88), `charts/library/common/templates/spawner/_metrics.tpl` (missing fail case, line ~19), `charts/library/common/templates/lib/pod/_topologySpreadConstraints .tpl` (not templated, no validation)
- Impact: Users who set affinity get a hard failure; storage class parameters and CNPG monitoring queries cannot be configured through values.
- Fix approach: Implement affinity rendering with validation, or document it as unsupported in the schema. Add the missing CNPG custom-query configmap and metrics fail case, each with a `failedTemplate` unit test.

**Tracked FIXME / upstream workarounds:**
- Issue: Tailscale addon carries a workaround for an upstream issue.
- Files: `charts/library/common/templates/addons/_tailscale.tpl` (line ~78, references tailscale/tailscale#8188)
- Impact: Behaviour depends on an upstream bug that may be fixed; the workaround may become dead code or break when upstream changes.
- Fix approach: Re-test against current Tailscale and remove the workaround when the issue is closed.

**Stale or unvalidated CI lint paths:**
- Issue: `tc-lint.sh` has an unfinished TODO to lint `ci/*values.yaml` files, and a Helm dependency lint step is commented out.
- Files: `.github/scripts/tc-lint.sh` (line ~80 TODO; line ~162 FIXME, dependency lint disabled)
- Impact: Broken `ci/` values files are not caught by the lint job; they only fail in install tests.
- Fix approach: Add `helm template` with each `ci/*values.yaml` to the lint script, and restore the dependency check or document why it is disabled.

**Oversized template helpers and mixed-in validation:**
- Issue: The `common` library has about 9,000 lines of `.tpl` under `lib/` alone, and validation logic is spread over `lib/*/_validation*.tpl`, spawners and classes. Storage validation for CSI NFS/SMB has open questions about allowed mount options.
- Files: `charts/library/common/templates/lib/storage/_validationCsiSMB.tpl` (line ~31), `charts/library/common/templates/lib/storage/_validationCsiNFS.tpl` (line ~27), `charts/library/common/templates/lib/util/_chartcontext.tpl` (CIDR detection not implemented, line ~55)
- Impact: Hard to reason about which validation runs where; unvalidated mount options can reach the cluster.
- Fix approach: Move cross-key checks into one validation area per object kind, and decide on an allow-list for NFS/SMB options.

**Charts pinned to `latest` tags:**
- Issue: 262 chart values files in `charts/stable` and `charts/incubator` use `tag: latest@sha256:...`. The digest pins the content, but the tag is not a version, so Renovate and humans cannot see which release is running.
- Files: e.g. `charts/stable/adminer/values.yaml`, `charts/stable/android-8-0/values.yaml`, `charts/stable/anope/values.yaml`, `charts/stable/anything-llm/values.yaml`, `charts/stable/androiddebugbridge/values.yaml`
- Impact: Conflicts with the rule to pin to a version (`<version>@sha256:<digest>`). `appVersion` derived from `image.tag` cannot be meaningful for these charts.
- Fix approach: Replace `latest` with the upstream version tag in each chart when Renovate or a maintainer touches it. Track as a batch task rather than a single PR.

**Changes without version bumps are not detectable from the repository:**
- Issue: The version-bump check in `tc-lint.sh` only compares against `origin/master` at lint time; nothing in the repository records bump history for charts.
- Files: `.github/scripts/tc-lint.sh` (`check_version`), `charts/library/common/Chart.yaml` (`version: 31.0.0`)
- Impact: Users of charts cannot tell from the chart itself which change is in place beyond the `CHANGELOG.md` generated by CI.
- Fix approach: Keep relying on the CI check; no code change needed short-term.

## Known Bugs

**Pod security defaults are overridden in many app charts:**
- Symptoms: The `common` defaults are UID/GID 568 with restricted settings, but many app charts set root.
- Files: 618 values files under `charts/stable` and `charts/incubator` set `runAsUser: 0`; 13 set `privileged: true`; 8 set `hostNetwork: true` (counted by grep across the two trains).
- Trigger: Installing those charts with defaults.
- Workaround: Each override is only justified if the app needs it. Verify each with a short comment as required by the security rules. This is a debt list, not a confirmed bug, since some overrides are needed.

**Possible hard-coded example passwords in chart values:**
- Symptoms: Some values files contain literal password strings.
- Files: `charts/stable/collabora/values.yaml` (line ~8, `password: changeme`), `charts/stable/authentik/values.yaml` (line ~30, `password: my-password`), `charts/stable/answer/values.yaml` (line ~26, `super-secret-password`), `charts/stable/avm-exporter/values.yaml` (line ~58), `charts/stable/flame/values.yaml` (line ~29, `PASSWORD: flame_password`)
- Trigger: Install with defaults. Some of these may be example or placeholder values in documentation-like blocks rather than active defaults; each needs checking.
- Workaround: Override the value at install time. Remove defaults and generate secrets in templates or through `dependencies`, per the project rules.

**Deprecated `cnpg` migration path still in active code:**
- Symptoms: `cnpg.<name>.enabled` fails with a long migration message.
- Files: `charts/library/common/templates/values/_deprecations.tpl` (line ~48)
- Trigger: Any chart still using the top-level `cnpg` key.
- Workaround: Migrate to `dependencies.postgresql`.

## Security Considerations

**Credentials in plain values:**
- Risk: Literal credentials in `values.yaml` end up in git history and Helm release values.
- Files: see the list under Known Bugs above.
- Current mitigation: Project rules forbid it; `common` renders generated credentials into Secrets and `notes.showCredentials` defaults to `false`.
- Recommendations: Add a CI check (grep-based or schema-based) that rejects non-empty `password` keys in `charts/stable/*/values.yaml` outside `ci/`.

**Privileged and host-level settings:**
- Risk: `privileged: true` and `hostNetwork: true` widen the attack surface and bypass pod isolation.
- Files: 13 charts with `privileged: true` and 8 with `hostNetwork: true` under `charts/stable` and `charts/incubator`.
- Current mitigation: Only in individual charts; `common` defaults are `privileged: false` and `hostNetwork: false`.
- Recommendations: Require a comment justifying each override, and review them periodically.

**Mutable image tags:**
- Risk: `latest` tags change over time; the digest pin protects the content but not the intent. Renovate cannot propose a meaningful upgrade.
- Files: 262 values files, see Tech Debt.
- Current mitigation: Digest pinning.
- Recommendations: Move to versioned tags.

**Schema openness:**
- Risk: Unknown keys are accepted where `additionalProperties` is not `false`, so typos in values pass silently.
- Files: `charts/library/common/values.schema.source.json` (line ~454 sets `"additionalProperties": true`, which the rules allow only on the values root; this location must be checked to confirm it is the root object).
- Current mitigation: `test_schema.py` and the coverage checks.
- Recommendations: Confirm the `true` at line ~454 is on the root only, and add a check that fails on `true` elsewhere.

## Performance Bottlenecks

**Full schema check across all charts:**
- Problem: `test_schema.py` lints `common` against about 850 values files and takes several minutes.
- Files: `charts/library/common/test_schema.py`, invoked by `run_common_tests.sh`
- Cause: One `helm lint` per values file, run serially.
- Improvement path: Run in parallel (GNU `parallel` is already used by `tc-lint.sh`) and cache the bundled schema.

**Chart template rendering cost:**
- Problem: Every app chart renders the full `common` loader on each install, which evaluates all spawners, including ones that are unused.
- Files: `charts/library/common/templates/loader/_apply.tpl`
- Cause: Spawners iterate over all top-level keys even when disabled.
- Improvement path: Skip spawners whose key is absent early; measure with `helm template` on a large chart.

## Fragile Areas

**Generated schema and structure files:**
- Files: `charts/library/common/values.schema.json` (generated), `charts/library/common/complete-values-structure.yaml`, `charts/library/common/template-keys-structure.yaml`, `charts/library/common/docs/**`
- Why fragile: They must match source files exactly; the documentation notes they are not always up to date and can fail `--check` for unrelated reasons.
- Safe modification: Edit `schemas/` and `values.schema.source.json`, then run `generate_bundled_schema.py`, `generate_docs.py`, and both structure generators, committing only the changes that belong to the PR.
- Test coverage: `check_complete_values_schema_coverage.py` reports coverage; any gap is a blocker.

**Name-keyed collections and spawners:**
- Files: `charts/library/common/templates/spawner/*.tpl`, `charts/library/common/templates/loader/_apply.tpl`
- Why fragile: Every spawner reads from an arbitrary-key collection; a renamed key or changed object name changes generated resource names and selectors, breaking upgrades for ~800 charts.
- Safe modification: Treat any change to names or selectors as breaking. Add `helm unittest` cases that check the rendered name and selector before and after.
- Test coverage: Unit tests exist under `charts/library/common-test/tests/`, but coverage for selector stability across upgrades is not explicit.

**Helm 3.14 compatibility:**
- Files: `charts/library/common/templates/**`
- Why fragile: The library must stay compatible with Helm 3.14 while developed on Helm 4; newer template functions can silently break the CI matrix.
- Safe modification: Test with v3.14.0 locally before merging, not only the latest Helm 4.
- Test coverage: The `common-tests.yaml` matrix covers v3.14.0, v3.20.0 and v4.1.0.

**Chart version bump discipline:**
- Files: all `charts/stable/*/Chart.yaml`, `charts/incubator/*/Chart.yaml`
- Why fragile: About 800 charts; a missed bump or a bump in a non-master PR is easy to make and only caught in CI.
- Safe modification: Follow the SemVer table in `AGENTS.md`; rely on `tc-lint.sh`.

## Scaling Limits

**Repository size:**
- Current capacity: About 807 application charts under `charts/stable` and 1 under `charts/incubator`.
- Limit: CI matrix runs (lint, install per `ci/*values.yaml`) grow with every chart and every `common` change, which affects every chart.
- Scaling path: Restrict CI to changed charts (already done by `tc-lint.sh` with a chart list) and to the dependent charts of a `common` change.

## Dependencies at Risk

**Helm and Kubernetes floor:**
- Risk: `common` supports Helm 3.14 and Kubernetes 1.33 floors while CI and local tooling default to Helm v4.3.1. `Chart.yaml` annotations declare `max_helm_version: "4.1"`, which is below the Helm version CI uses for lint, install and release (v4.3.1).
- Impact: Charts may be documented as unsupported on the Helm version used by CI.
- Migration plan: Reconcile `trueforge.org/max_helm_version` in `charts/library/common/Chart.yaml` with the CI Helm version, or raise it when the matrix is verified.

**helm-unittest version pinned in CI:**
- Risk: CI pins helm-unittest in `.github/workflows/common-tests.yaml` (`helmUnitVersion`), which can lag the latest release.
- Impact: Tests pass locally and fail in CI, or the reverse.
- Migration plan: Update the pinned version with Renovate and test the suites against it.

## Missing Critical Features

**Custom CNPG monitoring queries:**
- Problem: `cluster.monitoring.customQueries` configmaps are not created.
