# AGENTS.md

These are the instructions for AI coding agents working in the TrueCharts repository, including GitHub Copilot, OpenAI Codex/ChatGPT, Claude Code and any other tool that reads `AGENTS.md`.

- **`AGENTS.md`** (this file) is the canonical, tool-agnostic source.
- **`CLAUDE.md`** imports this file and the scoped files below for Claude Code.
- **`.github/copilot-instructions.md`** is a short, self-contained summary for Copilot surfaces that only read that file.
- **`.github/instructions/*.instructions.md`** hold area-specific rules. Copilot applies them automatically through `applyTo`. Other agents **must read the matching file before editing**:

| When you change files in | Read first |
| --- | --- |
| `charts/stable/**`, `charts/incubator/**` (application charts) | [`.github/instructions/charts.instructions.md`](.github/instructions/charts.instructions.md) |
| `charts/library/**` (`common` library and `common-test` harness) | [`.github/instructions/common-library.instructions.md`](.github/instructions/common-library.instructions.md) |

When you change a rule, update `AGENTS.md` and the scoped files first, then keep `.github/copilot-instructions.md` in sync.

## Repository overview

TrueCharts is a catalog of Helm charts (~800 apps). All of them are built on one shared library chart, `common`.

| Path | Contents |
| --- | --- |
| `charts/stable/<chart>/` | Application charts. This is where almost every chart lives. |
| `charts/incubator/<chart>/` | Application charts that are not yet considered stable. |
| `charts/library/common/` | The `common` library chart (`type: library`), which provides all templates (`tc.v1.common.*`). |
| `charts/library/common-test/` | Test harness for `common`: helm-unittest suites in `tests/` and install-test values in `ci/`. |
| `templates/` | Templates used by `forgetool` to generate chart READMEs, etc. |
| `.github/workflows/` | CI: lint, install tests, common tests, release and the daily metadata refresh. |
| `.github/scripts/` | CI helper scripts, e.g. `tc-lint.sh` (chart lint plus the version-bump check). |
| `.github/renovate.json5` | Renovate config, which extends `github>trueforge-org/renovate-config`. |
| `run_common_tests.sh` | Local runner for the `common` unit tests. |

Every directory under `charts/<train>/` is treated as a chart by CI and release tooling. **Never put loose files directly in `charts/<train>/`.**

## Golden rules

1. **Keep changes minimal.** Stay within the requested chart or library component. Do not reformat, reorder or "clean up" unrelated files or charts.
2. **Bump the chart `version`** in `Chart.yaml` for every change to a chart, except changes that touch only that chart's `docs/` folder. CI (`.github/scripts/tc-lint.sh`) fails when a changed chart has the same version as `master`. Bump each chart once per PR, following the [SemVer rules](#versioning-semver) below.
3. **Do not edit generated files by hand.** This covers chart `README.md`, `CHANGELOG.md`, `.helmignore` and `icon*.webp`, which are generated by CI (`forgetool` and the daily workflow).
4. **Do not hand-maintain the `Chart.yaml` fields that `forgetool charts genmeta` rewrites.** Keep them as they are unless the task is specifically about them. They are: the `trueforge.org/min_helm_version`, `max_helm_version`, `max_kubernetes_version` and `train` annotations; `kubeVersion`, `apiVersion`, `maintainers`, `home`, `icon` and `sources`; and `appVersion`, which is derived from the main `image.tag` (e.g. `v0.10.0-omnibus` gives `0.10.0`).
5. **Do not commit build artifacts.** That means `charts/<train>/<chart>/charts/`, `Chart.lock`, `*.tgz`, `__snapshot__/` and the like.
6. **Leave routine dependency updates to Renovate.** It handles image tag/digest updates and `common` version bumps across charts, with automatic version bumps. Do not mass-update the `common` version in app charts unless asked.
7. **Do not change CI workflows, Renovate config or repository-wide tooling** unless the task is specifically about them.
8. **Never commit secrets, real credentials or default passwords.**
9. **Run the validation** described below and in the scoped instructions before finishing. If you cannot run something, say so explicitly in your summary or PR.

## Versioning (SemVer)

Chart versions follow [Semantic Versioning](https://semver.org/). The bump size matches the conventional-commit type used for the change; Renovate applies the same mapping automatically.

| Change | Chart `version` bump | Commit / PR type |
| --- | --- | --- |
| Breaking: removed or renamed values keys, changed defaults that need user action, changed ports/paths/object names, major app upgrade, storage/data migration | **major** (`x+1.0.0`) | `BREAKING CHANGE(<scope>): ...` |
| New feature or option (backwards compatible), minor app/image upgrade | **minor** (`x.y+1.0`) | `feat(<scope>): ...` |
| Bug fix, patch app/image upgrade, small default tweak | **patch** (`x.y.z+1`) | `fix(<scope>): ...` |
| Digest pin/update, metadata or other non-functional change | **patch** | `chore(<scope>): ...` |
| Changes only inside the chart's `docs/` | none | `docs(<scope>): ...` or `chore(<scope>): ...` |

- The scope is the chart name (e.g. `fix(plex): ...`), `common` for the library, or `ci` / `charts` for repository-wide changes.
- Don't use the `(helm-deps): update chart common ...` title for manual PRs. CI uses that title to recognise Renovate's mass `common` bumps and skips install tests for them.
- `charts/library/common-test` stays at version `1.0.0`. Do not bump it.

## Toolchain

Always test with the **latest stable releases** of Helm and helm-unittest. The supported floor is Helm **3.14**, Kubernetes **1.33** (`kubeVersion: '>=1.33.0-0'`), so do not rely on features newer than those unless the task allows it.

| Tool | Version to use | Install |
| --- | --- | --- |
| Helm | Latest Helm 4 release (v4.3.1 at the time of writing; CI lint, install and release also use v4.3.1) | `curl -fsSL https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-4 \| bash` |
| helm-unittest plugin | Latest release (v1.2.1 at the time of writing) | `helm plugin install https://github.com/helm-unittest/helm-unittest --verify=false` |
| pre-commit, yamllint, yamale | Latest | `pip install pre-commit yamllint yamale` |
| GNU `parallel`, `jq` | Any | Needed only for `.github/scripts/tc-lint.sh`. |

- Check the current latest versions on the [Helm releases page](https://github.com/helm/helm/releases/latest) and the [helm-unittest releases page](https://github.com/helm-unittest/helm-unittest/releases/latest). Don't reuse versions you remember.
- On Helm 4, `helm plugin install` needs `--verify=false` for helm-unittest, because the plugin source does not support verification. On Helm 3, omit that flag.
- To upgrade helm-unittest on Helm 4, run `helm plugin uninstall unittest` and then install it again. `helm plugin update` fails for git-installed plugins.
- CI runs the `common` unit tests with the helm-unittest version pinned as `helmUnitVersion` in `.github/workflows/common-tests.yaml`, which can be older than the latest. If a suite passes locally but fails in CI, check that version first.
- The `common` CI also runs a compatibility matrix (Helm v3.14.0, v3.20.0 and v4.1.0 on k3s v1.33 to v1.35), so library templates must keep working on Helm 3.14.
- Dependencies are pulled from `oci://oci.trueforge.org/truecharts`. Pulls occasionally fail with `unexpected EOF`; if that happens, retry `helm dependency build`.

## Validation

Run the checks for the area you touched (see the scoped instructions for details):

```bash
# Repository hooks (whitespace, line endings, YAML syntax, private keys, etc.) on changed files
# These do not include yamllint or markdownlint, see Style below
pre-commit run --files <changed files>

# Application chart (from the repository root)
helm dependency build charts/stable/<chart>
helm lint --strict charts/stable/<chart>
helm template test charts/stable/<chart> >/dev/null

# Same lint as CI, including the version-bump check against master
git fetch origin master
result_file=/tmp/lint_result.txt .github/scripts/tc-lint.sh '["charts/stable/<chart>"]' origin/master

# Common library
./run_common_tests.sh
```

Afterwards, remove generated dependency artifacts: `rm -rf charts/*/<chart>/charts charts/*/<chart>/Chart.lock`.

## Style

- YAML: 2-space indentation and a final newline (see `.editorconfig`). Must pass `.github/yaml-lint-conf.yaml`, which `tc-lint.sh` checks for charts.
- Markdown: must pass `.markdownlint.yaml`. Use `-` for lists; long lines are allowed. No hook or CI job runs this, so run `markdownlint` yourself.
- Go templates: follow the existing whitespace-trimming (`{{-` / `-}}`) and indentation style of the file you are editing.
- Keep comments in `values.yaml` short and useful. Do not remove existing explanatory comments.

## Commits and pull requests

- Use conventional-commit style for commits and PR titles, e.g. `feat(jellyfin): add hardware transcoding option`, `fix(common): correct service port validation`. PRs are squash-merged, so the PR title becomes the commit message.
- Target `master`. The exception is the `common` rework, see [`common2026`](.github/instructions/common-library.instructions.md#the-common2026-rework). Make one logical change per PR; separate unrelated chart changes into separate PRs.
- Use the organization's PR template, [`.github/PULL_REQUEST_TEMPLATE.md` in `trueforge-org/.github`](https://github.com/trueforge-org/.github/blob/main/.github/PULL_REQUEST_TEMPLATE.md). It is not in this repository, so tools that create PRs from a body do not pick it up: fetch it and fill it in, keeping its sections and checkboxes. Only check the boxes that apply.
- When an AI agent wrote the PR, say so with this notice in the Notes section of the template: `🤖 This PR is AI generated.` Use it instead of a "Generated with ..." line or similar tool attribution, which should not be added.
- In the PR description:
  - explain *what* changed and *why*
  - reference issues with `Fixes #<number>`
  - for breaking changes, describe the required user action or migration
  - list the validation you ran
- Mark unfinished PRs as draft (or prefix `[DNM]`).
